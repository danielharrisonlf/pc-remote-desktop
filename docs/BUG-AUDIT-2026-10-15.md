# Revisão de bugs — 15/10/2026

Escopo: branch Android `main` (React Native 0.2.1), branch `native/kotlin` (0.2.4-kotlin) e repositório Windows independente (0.2.2). A implementação e a revisão independente desta rodada usaram somente subagentes GPT-6.1 Sol, conforme solicitado. O protocolo continua na versão 1 com extensão opcional input.v1; contrato e exemplos permanecem idênticos entre as três checkouts.

## Correções

| Aplicativo | Defeito e comportamento corrigido |
|---|---|
| Kotlin | Alterar o volume por teclado/acessibilidade, sem arrastar, não concluía a interação. Agora há confirmação do valor final e o slider volta a acompanhar mudanças reais do PC. Timers são cancelados ao desconectar. |
| Kotlin | Navegar da tela de controle para configurações/pareamento podia manter a entrada remota armada. A navegação desarma e cancela movimento; retornar exige ativação explícita. |
| Kotlin | Um texto pendente recebido em segundo plano podia sobreviver à conexão original. Revisão, dedup e preview pertencem à sessão; após perda de conexão são descartados, sem reenviar conteúdo antigo. Retomar na mesma sessão conserva o evento original. |
| React Native | O marcador de eco JavaScript podia bloquear uma recópia legítima A→B→A. A supressão nativa é a autoridade, consumida na próxima alteração observada, inclusive não textual/sensível. |
| React Native | Uma confirmação atrasada de envio podia apagar um novo texto compartilhado. Um contador distingue cada compartilhamento, inclusive dois textos iguais, preservando o novo até seu próprio envio. |
| React Native | Uma tentativa de novo pareamento podia substituir o PC salvo antes da autenticação/gravação. O candidato só é publicado após welcome válido e commit cifrado; falhas preservam o PC anterior. Callbacks antigos são bloqueados pela geração da conexão. |
| React Native | SharedPreferences.apply retornava antes da gravação de credenciais. commit é verificado e falhas restauram o valor anterior; métodos são sincronizados para impedir leitura de candidato transitório. |
| React Native | Descrição e payload de clipboard podiam vir de cópias diferentes. Leitura manual, listener e baseline agora verificam a descrição do ClipData capturado antes de acessar texto, com foco obrigatório. |
| Windows | Pareamento publicava credenciais em RAM antes da persistência. Agora prepara um candidato e o publica somente após salvar. |
| Windows | Falha ao salvar revogação podia deixar a conexão utilizável. A sessão é fechada e o dispositivo bloqueado no processo imediatamente; a interface informa se a revogação durável exige repetir a operação. |
| Windows | Configurações concorrentes podiam divergir entre RAM, disco e inicialização. As alterações são serializadas, a publicação ocorre após salvar e o registro é restaurado em caso de falha; erros de rollback são informados. |
| Windows | Uma cópia local ainda não processada pelo listener podia ser sobrescrita por sincronização automática. A sequência nativa é verificada com o clipboard aberto, antes de esvaziar/escrever; conflito preserva a cópia. |
| Interface Windows | Polling bem-sucedido podia apagar um erro de ação; falha ao copiar podia indicar serviço offline. Erros de conexão e de ação agora têm estados separados. |

Rustls também foi corrigido; consulte [auditoria de segurança e pendências upstream](SECURITY-AUDIT.md).

## Limites e reprodução

Celular físico ARM64, OEM/Doze, câmera QR óptica, Wi-Fi físico/mDNS, múltiplos players reais, troca de saída de áudio e suspensão física continuam pendentes. As imagens API31/33 usadas anteriormente não disponibilizavam o módulo de scanner: inicialização e erro controlado não certificam leitura óptica. Não se promete eliminar todos os bugs ou manter conexão durante suspensão Android.

- Kotlin, pasta android: `gradlew.bat testDebugUnitTest assembleRelease assembleSizeBaseline lintRelease`.
- React Native: `npm run typecheck`, `npm run lint`, `npm test -- --runInBand`; pasta android: `gradlew.bat testDebugUnitTest assembleRelease -PreactNativeArchitectures=arm64-v8a` (repetir assembleRelease com x86_64 para emulador).
- Desktop: `npm run typecheck`, `npm test`, `npm run build`; `cargo +stable-x86_64-pc-windows-msvc test --manifest-path src-tauri/Cargo.toml`; `npm run tauri build -- --target x86_64-pc-windows-msvc`.

O smoke de clipboard ignorado altera temporariamente a área de transferência; antes de executá-lo isoladamente, preserve todos os formatos e suspenda a sincronização. Não registre o conteúdo original. A fixture Android e o servidor controlado são apenas ferramentas de validação, não substitutos de integrações no produto.

Semantica não estava disponível: as decisões e evidências são versionadas nestes arquivos, sem alegar persistência externa.
